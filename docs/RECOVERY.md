# 保存、分支与恢复

新增参考资料、预览确认及候选阶段恢复规则见[资料管理说明](SPDB_FEATURES.md)。

保存点包含当前范围的正文来源、角色名单、访问控制、记忆与情绪分析以及世界时钟和账本设置。分支使用独立范围；后续修改不会写回原分支。恢复会提升当前版本，旧候选和迟到处理结果不能继续提交。未完成分析的来源仍须重试，保存点不会把它们变成处理成功。

酒馆面板提供“保存点、撤销与分支”：建立命名保存点，读取列表后恢复，或撤销最近一次有保存点的操作。建立新分支会从当前状态复制，切换已有分支时用它的受管正文替换聊天内另一分支的受管正文；另一分支仍保存在数据库中，切回时重建。原聊天中不由 XLDB 管理的内容不属于保存点。

删除来源后，与它有关的旧保存点会移除；当前删除规则仍可读取时，普通旧备份或旧保存点不能恢复该来源及其影响。数据库及删除规则均丢失的灾难恢复有下述明确限制。编辑、访问设置、偏好纠正和世界配置仍可通过有效保存点撤销。此规则作用于执行删除的范围；已经建立的其它独立分支如也要清除，应在相应分支处理。

受管检索表随删除清理；清理失败时保留待处理记录，重新同步或重试后台处理会继续完成。权威库中的来源正文、分析和相关纠正记录会移除或清空。这是应用层删除，不承诺擦除SQLite空闲页、LanceDB历史文件、用户导出、旧备份或外部模型服务日志。Agent文件宿主会清理已结束任务的请求与结果；没有可识别任务回执的文件不会擅自删除。

正文恢复过程中断时重新绑定同一聊天，以数据库中的状态重新载入正文；不要手工删除聊天元数据中的恢复标记。换聊天后必须重新绑定。Agent 对应操作见 [Agent 接口](AGENT.md)。

撤销或恢复后若提示“检索清理待重试”，正文与权威状态已经提交；点击“同步更改”继续清理，不要重复撤销。核心重启、Agent CLI启动及下一次检索会先续做已登记的清理任务；清理完成前不会用旧索引生成。

## 数据库备份

在项目根目录执行。数据库、备份及恢复临时文件必须位于该安装目录的 `.local/` 下。以下为默认酒馆路径，Agent 请替换为实际使用的 `.local/agent/data/authority.sqlite`。

```powershell
node tools/backup.mjs create .local/data/authority/xldb.sqlite
```

命令使用 SQLite 一致快照，可在当前核心运行期间创建备份。结果返回备份目录及含 SHA-256 的 manifest；备份包含数据库中的私密正文和角色状态，请按用户数据保管，不要作为诊断日志公开。

恢复前停止使用这个数据库的所有 XLDB 核心、Agent 进程，然后执行：

```powershell
node tools/backup.mjs restore .local/backups/实际备份目录 .local/data/authority/xldb.sqlite
```

恢复会核对备份哈希、表结构与 SQLite 完整性，再合并当前库已删除来源的墓碑，使普通旧备份不能复活当前已经删除的内容。相关派生状态和不安全保存点随之失效。原备份不修改；恢复前数据库及其辅助文件移到返回的 `recoveryDirectory`。恢复完成后重新启动核心、绑定聊天并检查状态；检索索引由有效来源重建。

进程保护标记使正在使用的数据库拒绝恢复，报错 `backup_database_active`。不要在服务仍运行时移除标记。若进程恰好在初始化保护目录时被强制结束，`<数据库路径>.xldb-guard/active/owner.json` 可能缺失或不完整，此时不能自动确认所有者；先确认所有使用该数据库的进程确已停止，保留该 `active` 目录副本，再手动将它改名为故障留档，之后重试。正常的已退出进程标记可自动回收。

当前备份不包含模型连接凭据、角色卡、世界书或整个酒馆安装。私有连接配置须单独保管；酒馆原生聊天文件由酒馆自己的备份机制保护。恢复命令不会自动修复外部酒馆文件。

## 数据库丢失或损坏

正常库回滚仍使用 `restore`。数据库丢失时，使用独立新路径执行：

```powershell
node tools/backup.mjs recover .local/backups/实际备份目录 .local/recovered/authority.sqlite
```

`recover` 先核验备份，再写新路径；目标若是已受本项目保护的损坏库，会先保全原db/wal/shm文件。目标是有效数据库时拒绝，不以灾难恢复覆盖正常数据。返回 `recoveryDirectory` 为保全位置，新路径时为null。

返回 `deletionRules: target` 表示合并了目标仍可读取的删除规则；`backup_only` 表示只能恢复到备份时的状态，**无法保证保留备份之后的删除**。原数据库及其规则均不可读时，程序不会编造后续删除历史。请按这一范围核对恢复结果，再将宿主指向新库。恢复过程中断的旧文件保全目录须留存，直到新库及宿主正文确认一致。


## 主动消息已发送但后台整理失败

已发送回执和宿主消息独立保留。若界面提示后台整理失败，使用“同步更改”重试该来源的失败阶段；不要重新生成或重发主动消息。重试成功后，原消息继续使用相同来源和投递标识。宿主写入结果未知时，先在当前聊天确认已有消息，再用主动陪伴面板对账；不能将未知状态当作未发送自动重试。

承诺记录、定向关系、画像来源与初始化出处随权威数据保存。自然模糊是当前有效来源和对应时钟上的派生投影，撤销复习来源会撤销其刷新效果。主动性授权、联系控制、已发送回执及用户画像纠正的恢复边界按各模块的独立用户控制规则处理，不随剧情重放而重复投递。
