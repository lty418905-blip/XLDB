# XLDB Tavern Helper MVP

## 自动安装入口

将交付 ZIP 解压到独立的D盘目录，运行根目录 `START-XLDB.cmd`。它自动补齐本地运行时、安装依赖并启动核心，然后打开酒馆页面。在该页面的 Tavern Helper 加载同目录的 `XLDB-酒馆.js`，JS 自动配对、加载主插件并读取配置。不要把核心文件直接导入酒馆，也不需要服务端插件。浏览器本身不能执行本机程序，所以解压后仍需运行一次启动器。

酒馆助手→脚本→导入，选择包内 `XLDB-酒馆.json`，选择全局或当前角色脚本库并启用它。导入器默认关闭新脚本，所以需要打开该脚本开关。JSON只是助手的脚本导入格式，内容与同包JS一致；也可新建脚本并粘贴 `XLDB-酒馆.js`，无需编译。不要把 `.js` 文件选进只接受 `.json` 的导入框。

支持 Windows x64、核心与浏览器同机。默认酒馆地址8000端口；自定义地址通过 `START-XLDB.cmd -TavernOrigin http://localhost:你的端口` 指定，本机核心端口可用 `-Port` 修改。模型 API URL、密钥及模型由你填写，各阶段仍独立可配；不会猜测或从酒馆私有设置提取 API 密钥。已有配置直接读取。连接令牌保存于当前酒馆站点的浏览器本地存储供重连；配对码只用一次且有时限，JS读取后从页面地址移除。左下角“XLDB 连接”可检查连接或清除该浏览器保存的连接，不删除数据库。

关闭并重新打开酒馆后，核心仍在运行时自动重连；电脑重启后，再运行 `START-XLDB.cmd` 即可。安装器不注册系统开机服务。`tools/stop.ps1` 只停止该安装记录的核心进程。不要同时启用自动连接脚本和旧的直接加载脚本。

下文直接加载 `adapters/sillytavern/xldb.js` 的手工方式仍可用。

资料工作台、正文纠正、模板迁入、后台进度和恢复预览见[资料管理说明](SPDB_FEATURES.md)。

将 [`adapters/sillytavern/xldb.js`](../adapters/sillytavern/xldb.js) 作为 Tavern Helper 的 JavaScript 脚本加载。它是直接加载的 JS，不需要编译。脚本函数在 Helper iframe 中执行，面板挂载到同源父页面；左下角 `XLDB` 按钮打开固定工作台，右下角保留可折叠的变量面板。

## 工作台、变量面板与生理状态

两个视图共享同一份玩家可见状态：概览显示世界／现实时间、玩家名、余额和物品种类；资产、物品与最近交易可分别查看。交易列出本人已生效购买、退款和消耗的物品、数量与币种，不跨币种合计。变量面板支持折叠、明暗主题、左右位置和字号；固定工作台的“设置与资料管理”保留完整配置和管理入口。提交后立即请求新投影，后台独立变化每15秒空闲轮询；现实时间每秒显示。切换聊天、模式或分支会清空旧状态。地图栏支持跑团地理状态、分层示意图及布局拖动，见 [地图配置、JSON 格式与恢复](MAP.md)。

“设置与资料管理 → 虚拟角色生理状态 → 读取生理设置”可启用模块、选择跟踪角色和需求。酒馆须在独立模型配置中填写 `physiology`。六项日常需求为饮水、进食、小便、排便、睡眠和精力；持续身体影响、跑团生殖状态与唤起状态可独立开关。所有项目默认关闭，只处理选择的虚拟角色。伴侣模式仅保留日常需求和持续影响。

生理状态随已接受正文和对应时钟更新，可按角色查看、注明原因纠正、设定纠正的知情范围并撤销纠正。常驻变量面板只展示玩家可知内容；角色输入只获得角色自己的可知状态。未知剧情时间保留未知，不按现实等待代谢；未接受候选、回忆、计划和传闻不应创建当前状态。当前需求阶段是用于角色表现的启发式值，尚无长期体验校准。

这条适配路径处理用户明确绑定的一张角色卡聊天，各 NPC 拥有独立身份、知识和情绪。启用原生聊天后接管普通发送的上下文组装；另保留面板中的受控候选入口。真实宿主、模型质量和长期体验分别验收。

当前原生模式仍在测试，现行首字目标按用户要求为60秒。早期霍格沃茨 v12 七轮测试发生过转场、身份及提取失败；2026-09-20伴侣长测的基线包完成90轮后在第91轮阻塞。本候选针对承诺对象绑定、人物归属、召回及偏好作用范围进行了修正。原始失败和修复后的验证分别记录在源码工作区 `PROJECT_STATUS.md`，不能把合成测试或混合版本续跑当作固定版本长期质量通过。

## 启动、绑定与停止

新聊天绑定后默认跑团／角色扮演，单NPC也适用。“模式与时钟”可切换伴侣、设置显示时区，并保存导演启停选择。导演默认启用，须配置独立 `director` 模型；它在本轮状态同步后规划，再向各 NPC 提供有知情依据的局部建议。关闭导演后继续角色回复；伴侣不运行导演。切换会取消旧候选，模式各自保存经历和时钟，切回恢复原范围。首次绑定旧世界时按已有世界时钟归属保留原数据。

伴侣时钟同步核心所在系统的当前时间；可填 `Asia/Shanghai` 等 IANA 时区，留空跟随系统时区。跑团时钟只显示正文推进后的剧情时间，未设置日期时显示未知；现实等待不推进剧情。时区改变不改事件时间。核心和JS必须同时升级：`interaction` 返回活动scope及revision，后续请求携带 `interactionRevision`；`prepare` 另携带稳定 `userSubmission:{expectedVersion,operationId,userMessageId,acceptedAtMs}`。过期模式请求会失败，重新绑定核对后再继续。

先在 `D:/XLDB` 运行 `tools/install.ps1`，再以 `npm start` 启动本地核心。默认核心地址为 `http://127.0.0.1:4318`；首次启动的 bearer token 位于 `D:/XLDB-private/local-token.txt`，私有配置文件为 `D:/XLDB-private/config.json`。在面板中填写 token 后，选择世界 ID 并点击“绑定当前聊天”。

当前拒绝群聊和没有当前角色的聊天。分支由 XLDB 面板管理，初始为 `main`。聊天切换会停用绑定并丢弃未接受候选。“禁用本聊天”也会取消候选和等待中的结果，但不会删除聊天、核心数据或私有配置。启用原生模式会处理当前聊天的非系统正文，包括开场白，建议从新聊天开始。已绑定其他 XLDB 范围的消息不能直接改绑。

## 初始化、资源、画像与主动陪伴

“从角色卡与世界书初始化”先列出当前角色卡、内嵌和关联世界书中启用的条目。勾选来源并配置 `initialization` 后预览，核对 NPC、知情范围及冲突，再确认应用。秘密按读者限定；示例台词和未来设想不写成已发生经历。当前卡与关联书可能同时含有同一条目，选择所需来源即可。

应用后可查看来源与产物。生成前核对来源变更；来源停用、删除或正文改变时，先预览并确认撤销受影响的参考资料，原资料不再进入角色输入。恢复相同来源仍须审查后恢复；角色设定发生冲突时保留已接受历史，由用户核对。

“NPC 资源控制”显示上限、优先角色和暂停角色。降低上限不删除角色历史；角色需要参与时按批恢复神经状态。每批结束后才回收资源。

`commitment` 独立提取约定候选；本地按正文与时钟验证期限。已建立的无限期约束常驻于适用角色输入，未知期限不会被当成永久。履行、取消、修订和正文撤销会更新承诺投影。

跨轮说“好，就这样约定”使用 `confirm` 引用既有提议，继承原条款并累计有来源的同意；多人约定缺少任何必要参与者同意时仍为提议。确认不会改写条款、扩大读者或代替他人同意。

“伴侣画像与主动陪伴”只在伴侣模式使用。先填写明确的真实用户 ID，再分别启用画像学习、策略应用、主动陪伴和定时唤醒；四项默认关闭。面板支持分类限域、条目纠正与删除、联系时区和时段、最小间隔、未回复上限及忙碌截止时间。`profile`、`strategy`、`proactiveDecision`、`proactive` 各有独立模型配置；决策可延后或放弃主动联系。已接受的主动消息作为 assistant 来源学习。

结果为 `unknown` 时不会自动重发。面板可核对当前聊天的稳定投递标记；没有标记时须填写实际存在的 assistant 消息 ID，确认已发送后关联现有消息。确认未发送则释放后续机会，不重发原候选。定时检查仅在插件启用、宿主运行且用户授权时执行。

## 原生聊天与自动身份

配置 `identity`、`perspective` 及其他实际使用的文本模型阶段，绑定聊天后点击“启用原生聊天”。若为回复前的用户正文筛选配置了 `inputPerspective`，该阶段使用它；留空则回退到 `perspective`。脚本读取当前角色卡、内嵌世界书与关联世界书中启用的条目。后台先依据正文出现的人物和有限索引选源，再提取逐字身份、稳定人格片段；保存来源 ID、引用和内容 SHA-256。身份不是已发生历史，世界书剧情不会直接进入记忆。每次原生发送重新读取资料；来源变化或删除导致无法验证时停止生成，直到重新提取或用户补充身份。

只有资料不足时才在“多人场景”补充姓名、别名和身份。一名 NPC 也可工作。人工补充不授予角色知识；自动模式的在场、听闻和知识只从正文及有引用依据的连续场景中确定。代词消歧依赖的原文被编辑或删除后，相关派生材料失效。

每个参与回应的 NPC 分别接收自己的画像、可见正文、记忆与情绪。多人或包含私密知识时，`front` 阶段生成该 NPC 面向玩家的候选言行，视角环节再次筛选；最多同时处理两个 NPC。酒馆的当前模型作为最终叙述者，只接收有玩家视角证据的公开言行。只有一名回应角色，且该角色当前与历史观察均被判定为玩家可见的台词或外在行为时，才直接由酒馆模型生成，省去一次后台正文生成和出口提取。身份画像不代表共同经历。

新用户正文先持久保存，同步完成本轮视角、记忆、情绪、偏好及启用的世界状态更新后才召回和生成。必要阶段失败时保留已接受用户正文并阻止当前回复；修复后重试。助手正文仅在宿主接受后学习。原先延后本轮用户学习的快速路径已移除，真实首字延迟与失败恢复时间见源码工作区的长对话测试记录。

模型语义误判仍需真实质量验收。逐字引用、宿主玩家姓名和角色目录校验只能证明来源与结构，无法独立判断任意自然语言的受众含义；模型把私语错误标为公开仍可能造成泄露。这是尚未关闭的质量限制，不能称为确定性的自然语言隐私隔离。

普通发送与完整回复自动同步，编辑、删除后也自动同步；可用“同步更改”重试失败。中止的流式片段不提交长期状态。当前支持 OpenAI 兼容的对话补全入口；续写、重生成、滑动会被阻止，需先编辑或删除，再重新发送。外部扩展若在 XLDB 的最终钩子之后改写请求，可能破坏隔离；并用扩展须独立验收。

## 十三个独立模型配置

“读取本地配置”认证读取 `GET /v1/config`，“保存全部配置”以完整对象 `PUT /v1/config`。各阶段拥有独立 URL、密钥和模型字段：

- `memory`：从已接受正文提出记忆候选。
- `emotion`：提出 OpenHer 情绪与稳定关系候选。
- `preference`：提出可纠正的用户偏好候选。
- `rewrite`：整理已获准模糊记忆的表达。
- `calculation`：只从当前文本提取候选操作和操作数。
- `front`：生成用户明确请求的候选正文。
- `embedding`：可选的受限检索嵌入。
- `reranker`：可选的受限检索重排。
- `inputPerspective`：回复前只筛选当前 user 正文的视角；可配置较快模型，留空时回退 `perspective`。它与后者共享同一视角合同和状态权威，不另建结果或重复推理。
- `perspective`：对多人场景中的视角、在场范围和未知事项提出候选；它不会改写客观事件。
- `outward`：从已知角色的候选回复中筛选玩家可听见的台词和可见动作，使用独立 API 设置；它不授予 NPC 知识，也不写入状态。原生多人或含私密知识的回复需要配置此项。
- `identity`：从当前卡和关联世界书选择并提取独立身份原文。
- `world`：启用世界状态后提取时间、购买与消耗候选，由脚本校验原文并计算实际变化。

文本模型的“思考模式”可选服务默认、关闭、开启。默认不发送额外参数；明确选择后，`api.scnet.cn` 按其文档发送 `enable_thinking`，其他兼容服务发送 `thinking.type`。实际是否支持由服务决定；本轮 SCNet 的 DeepSeek-V4.1-Flash 即使收到关闭参数仍返回推理 Token，未验证关闭有效。嵌入和重排不使用此项。文本请求输出上限为 16,384 Token、超时 180 秒；服务返回 `finish_reason=length` 时报告 `model_output_truncated`，不会接受截断内容。

所有阶段默认空白，只有实际使用时才需要配置。前台 API 可不填密钥，以支持本地或无需认证的端点。token 只保留在页面内存；模型密钥只在密码输入框与用户明确保存的 `D:/XLDB-private/config.json` 之间传递，适配器不将其写入聊天、日志或浏览器存储。

`embedding` 和 `reranker` 都为空时，核心显式使用 **BM25-only**，不会隐式请求远程模型。若选择 SiliconFlow，可填写完整端点 `https://api.siliconflow.cn/v1/embeddings` 与 `https://api.siliconflow.cn/v1/rerank`，并先尝试 `BAAI/bge-m3` 与 `BAAI/bge-reranker-v2-m3`。请在 [SiliconFlow 平台](https://cloud.siliconflow.cn/) 创建 API Key，并参照其[快速开始文档](https://docs.siliconflow.cn/docs/userguide/quickstart)选择平台可用的模型。不要从开发用密钥文件、浏览器存储或聊天读取密钥。

## 多人场景

面板的“多人场景”区域显示独立身份，也可补充缺失身份。展开每一行的“情绪参数（OpenHer）”可分别设置五项驱动力基线，以及受挫衰减、关系与新颖需求增长、事件保留比例和稳定关系变化率；默认值依次为 `0.5`、`0.08`、`0.15`、`0.05`、`0.9`、`0.05`。输入控件标出合法范围，核心仍是最终校验权威。以下目标、在场复选框与“场景/直接”设置适用于面板的受控候选入口；原生自动模式自行依据正文识别，不能用复选框为角色添加知识。

神经学习默认开启。新角色默认使用稳定身份生成的随机驱力基线；关闭该选项才使用五项手动值（默认0.5）。旧配置已有明确基线时保持手动模式。另可调整学习率（默认0.02）、相变阈值（2）、温度系数（0.12）与最低温度（0.03）。参数随NPC保存；权重、递归状态和随机状态由核心管理，不由模型或前台直接填写。修改参数会触发旧分析重算，升级前建议使用恢复工具保留一致备份。

`POST /v1/scene/configure` 保存名单，`/v1/scene/inspect` 显示每名 NPC 当前允许看到的材料，`/v1/scene/reconcile` 同步所有带 `extra.xldbScene` 标记的当前消息。旧 `extra.xldb` 消息不会被场景同步导入。用户处理失败时，面板显示错误，保留用户正文，不生成或插入助手回复。

2026-09-20协议更新需要同时更新核心与JS。同步请求增加 `expectedVersion`、`operationId`，返回权威 `bindings` 并保存消息revision。名单、世界设置、访问、偏好、身份提取和原生上下文请求也携带 `expectedVersion`。旧快照发生冲突时停止，不能靠重新绑定版本覆盖新正文。原生上下文返回30分钟有效的 `contextTicket`，完整回复通过 `/v1/scene/native-accept` 接受；权限、名单、模型配置、来源或恢复变化会使旧候选失效。核心重启后未接受票据失效，须重新生成。

发生同步冲突或接受回执丢失时，可使用“使用核心当前正文（覆盖受管改动）”重新载入当前范围；此操作以核心正文覆盖本地受管编辑，请先核对要保留的内容。未确认接受的原生回复有独立候选标记，重新启用自动模式不会把它冒充旧历史导入；若核心实际已接受同一候选，恢复会按身份补回绑定，不重复插入正文。

生成场景候选前，脚本已提交本轮用户输入；接受时只追加最终回复，并保留核心返回的消息 ID、修订、场景信封、发言者和依赖关系；随后仅调用一次 `POST /v1/scene/accept`。后台观察、记忆、情绪、偏好和视角材料只在管理区显示，不会成为聊天消息。

## 世界时间与账本

先填写独立 `world` 模型，再展开“世界时间与账本”。选择剧情或现实陪伴模式，填写带时区的初始时间、玩家姓名及初始余额/物品。每项初始值分别选择可获知完整数值的角色；管理者看见全部状态不等于 NPC 都可知。保存后按当前有效历史重算，未启用的旧聊天不自动启用或改写。

剧情模式由已接受正文中的当前时间线索推进；计划、回忆、假设和重复事件不推进。陪伴模式随现实时间前进，持久时间下界防止重启后倒退。购买须有明确的物主、物品、阿拉伯数字数量、单价和单位；脚本按小数金额精确扣款并增加库存，消耗减少库存。退款只能退回一笔已接受购买：当前正文必须明确退回并给出阿拉伯数字数量，候选以原购买的 `sourceId`、`revision`、`effectId` 精确引用；核心按原单价返还余额并同步减少库存。退回量不能超过该购买尚未退回的数量，库存不足、观察者无原交易知情权限或候选不完整时整批不提交，可见错误留待纠正重试。退款金额、币种换算、中文数字和任意交易类型尚未支持。

跨轮议价尚未形成正式交易记录：价格只在前文出现、当前只确认“成交”时可能漏记。当前需要成交正文明确重述数量与单价。拿起询价、嫌贵放回、仅报价三个固定模型样本未误扣款，但不代表任意复杂叙述均能正确区分。退货不会按自然语言猜测原交易或金额；无法唯一关联已接受购买时不提交，不能把当前基础账本用于完整交易管理。

启用账本的本轮须先完成已接受事件处理，再生成基于新时间/余额的回复；所有模式都遵守生成前同步屏障。模型只提交候选，不直接写余额、库存或已确认时间。单独观察到购买不代表获知完整余额。

## 保存点和恢复

“保存点、撤销与分支”提供保存、回滚、撤销和分支切换，正文与其记忆、情绪及世界状态一起恢复。恢复中断后重新绑定同一聊天。数据库备份和故障恢复见 [恢复说明](RECOVERY.md)。

“重新生成上一条回复”先显示替代候选；拒绝保留原回复，接受只在原位置替换助手回复，不追加用户消息。该面板入口与酒馆原生的重生成/滑动按钮不同，后者仍不支持。

当前生命周期组件与原生 Agent 场景已有验证；真实酒馆受控重生成产生了候选，但后台记忆提取曾失败，提示修正后的恢复又遇模型限流。完整酒馆生命周期仍未通过，勿将下述接口说明当作实机验收结果。

“场景”模式先根据本轮明确的经历、听闻和思想提取知识片段；在场名单只是权限上界，不会自动使全部 NPC 得知每个片段。“直接”模式表示用户只向当前目标说话，其内容只对目标可见。视角含糊或模型输出不合规时阻止生成/提交并显示错误；可修改输入明确参与者后重试，不能靠扩大在场范围绕过私密边界。

管理区按 NPC 展示当前记忆、数值情绪与偏好；每条记忆的“更新访问”调用 `/v1/scene/access`，可以缩减为大意、感觉、锚点或隐藏。源消息编辑或删除后，点击“同步更改”；依赖旧来源的已生成回复被标记为待复核，不再用于记忆。修正这些正文后再同步。已写进聊天但分析失败的候选不能用“拒绝”伪装撤销，应同步重试或编辑/删除对应消息后同步。

偏好条目提供启用勾选、纠正文本和“保存偏好”，写入 `/v1/scene/preference`，绑定所选NPC及原始来源。待复核列表提供“按当前来源重新确认”：仅在人工核对正文仍成立后使用；它更新父来源依赖，再重新整理，不能恢复已删除父来源。未核对的后续依赖仍保持待复核。

名单及情绪参数保存在核心数据库；浏览器选择偏好若因 Helper 沙箱无法保存，重新加载后填写同一世界 ID 并绑定即可取回名单。新增或移除角色应保留已有稳定身份；姓名相同不代表身份相同。

## 单角色兼容入口

“生成候选”向本地核心发送 `POST /v1/generate`。核心在当前世界、会话、分支和角色范围内读取受限上下文，然后以用户配置的 `front` 阶段请求外部 API；XLDB 不托管推理服务。面板只显示结果预览。

伴侣模式的旧单角色入口在生成前先写入并处理 user 消息；“接受并提交”只新增助手回复。`extra.xldb` 保存稳定 ID、修订、作用域和接受时间。拒绝或重试不删除、不重复学习已提交用户正文；修改或删除它须使用正文编辑/删除。

“同步更改”只发送当前作用域、带 `extra.xldb` 的原始酒馆消息到 `POST /v1/reconcile`；原始正文是 `mes` 字段。核心请求重新处理的记录再逐条发送到 `/v1/process`。如果接受后某次处理失败，已有的受管消息留在聊天中；同步会登记尚未被核心确认的消息并重试，避免再次追加相同候选。

“查看当前状态”调用 `POST /v1/inspect`，展示当前允许读取的记忆细节、大意、感觉、锚点、保护事实和遗忘提示，以及偏好和情绪。可用 `POST /v1/access` 更改记忆的 `clear`、`gist`、`feeling`、`anchor`、`hidden` 访问层级；可用 `POST /v1/preference` 启用、关闭或编辑偏好。除配置读取外，核心操作均为认证 JSON POST；配置保存是认证 JSON PUT。

## 数值结果

需要数值计算时，`calculation` 模型只能提出当前文本中已有的操作数和运算。核心用 `BigInt` 有理数脚本验证并计算，前台回复只能引用经过验证的结果占位符；脚本再插入最终数值。缺少明确操作数、单位、运算方式或时区时，核心要求补充信息，不让模型自行计算或写入数字结果。

## 正文与后台的边界

记忆提取、情绪、偏好、遗忘及计算资料保存在本地状态或管理面板，只向前台模型提供筛选后的依据；不会另写为聊天消息。生成前提交用户输入；接受按钮只追加前台最终回复。验收聊天中的承诺和金额是合成用户输入，不是后台分析的展示方式。模型仍须遵循不输出后台字段与处理过程的提示；用户可以在候选预览中拒绝不合适的正文。
