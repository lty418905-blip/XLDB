# 资料管理、迁入与处理进度

本批借鉴 SPDB 的使用方式，以 XLDB 的来源和角色权限为准重新实现。没有采用 SPDB 源码或运行时；剧情导演、主动陪伴和称谓模块不属于本批。

## 酒馆面板

绑定当前场景后打开以下折叠区：

- **资料工作台**：按关键词与类型查询正文来源、角色身份、记忆、偏好、情绪、世界时间、余额、库存和迁入资料。管理员可看来源正文；“角色所知”须填写 NPC 稳定 ID，只返回其当前访问粒度。界面不补造尚未建模的位置和任务。
- **正文纠正**：编辑来源正文，点击“预览纠正”，核对后确认。核心校验原修订与场景版本，重算受影响的资料，并刷新酒馆中的同一条受管消息。删除也先预览。模型候选没有修改已接受来源正文的权限。
- **记忆与偏好保护**：沿用持久访问粒度与偏好纠正；这些控制绑定来源内容身份，不绑定表格行号。它们不会冻结新接受的剧情事件。余额和库存仍由正文中的合法交易确定性更新；不能直接编辑情绪神经权重。
- **后台处理进度**：显示来源 ID、修订、各角色的记忆/情绪/偏好阶段，以及必要材料是否就绪。展开时定期刷新。失败按限流、格式、配置、传输或冲突分类；“重试该来源未完成阶段”会先完成其必要前序，只重做失效或缺少的阶段。未提交阶段不产生长期神经学习。
- **模板与参考资料迁入**：导出当前身份与世界设置为 JSON，可保存为独立模板。粘贴模板或下述参考资料格式后，先预览新增、重复、删除边界及冲突，再确认。模板没有 API 密钥、聊天历史或神经权重；修改模板副本不影响原聊天。
- **保存点、撤销与分支**：先预览恢复或撤销。确认绑定预览版本与检查点；状态变化后须重新预览。一次模板迁入对应一个撤销操作。已删除参考资料不会经旧保存点或分支复活。
- **连接检查与批量配置**：检查核心、认证、宿主消息能力、绑定和待恢复状态；检查不调用模型。填写共用连接并选择环节后，再“保存全部配置”。各环节仍可独立修改，embedding/reranker 默认不勾选。

同一聊天的正文可能已经在其他入口改变时，先重新查询。纠正或恢复丢失响应后会停用当前绑定，重绑时从核心载入受管正文，避免旧宿主文本反写覆盖。

## 参考资料格式

这是有限 JSON 映射，不是任意 SPDB 文件、SQL 或可执行模板导入器。

```json
{
  "format": "xldb-reference-import-v1",
  "rows": [
    {
      "table": "notes",
      "row": "old-port-code",
      "text": "旧记录称港口使用蓝灯作为信号。",
      "knownBy": ["npc-a"],
      "occurredAtMs": null
    },
    {
      "table": "notes",
      "row": "unconfirmed-note",
      "text": "待管理员核实的旧资料。"
    }
  ]
}
```

`knownBy` 必须是当前名单中的稳定角色 ID；省略时不授予任何 NPC。未知发生时间保持 `null`，导入时间另记，不等同角色当时经历过事件。每条保留文件内容哈希、表与行来源；即使参考文字写着“余额75”“支付25”或“好感80”，也不会扣款、重放经历或训练情绪。

同一 scope 内 `table + row` 标识同一参考条目。另一个文件重复携带未改条目时跳过；相同标识的内容、知情范围或时间变化会报告冲突并拒绝整次迁入。当前界面不提供自动合并：可取消并核对原资料；若确实是独立新资料，使用新的明确行标识。删除形成永久边界，同标识不会因修改文件其他行而复活。管理员可在工作台预览并确认删除。

模板格式为 `xldb-scene-template-v1`，字段为 `name`、`roster`、`worldSettings`。使用面板导出作为样例。已有接受历史时，改变世界初始账本/时钟的模板会被拒绝，防止导入余额后又重放旧支付。可在新场景使用模板。

## Agent 与 HTTP

HTTP 使用既有令牌与 scope。以下路由共享同一状态权威：

| 操作 | HTTP POST | AgentRuntime / CLI operation |
| --- | --- | --- |
| 工作台 | `/v1/scene/workbench` | `workbench` |
| 进度 | `/v1/scene/progress` | `progress` |
| 精确重试 | `/v1/scene/retry` | `retryPending` |
| 正文纠正 | `/v1/scene/source-correct` | `correctSource` |
| 导出模板 | `/v1/scene/template-export` | `exportTemplate` |
| 迁入预览 | `/v1/scene/transfer-preview` | `previewTransfer` |
| 迁入确认 | `/v1/scene/transfer-apply` | `applyTransfer` |
| 删除参考资料 | `/v1/scene/reference-delete` | `deleteReference` |
| 恢复预览 | `/v1/scene/restore-preview` | SDK `previewRestore` / CLI `restorePreview` |

迁入确认传 `document` 与预览的 `expectedVersion`、`previewId`，并提供稳定 `operationId`。预览不写数据库；`previewId` 是 scope/版本/内容的绑定摘要，可跨 CLI 进程使用，不是认证凭据。重试同一操作保留 `operationId`，返回当前权威版本而不重复应用。

正文纠正传 `sourceId`、`revision`、`text`（`null` 表示删除）与 `expectedVersion`、`operationId`。恢复确认向 `restore` 传 `checkpointId` 与 `expectedVersion`；撤销向 `undo` 也传预览 `checkpointId` 与 `expectedVersion`。SDK 中恢复及撤销须 `await`。恢复后 `cleanupPending:true` 只重试索引清理，不重复撤销。

## 近期上下文与恢复

当前角色的近期记忆与长期检索结果分栏组合，同一记忆去重。近期从权限/时间/访问粒度投影后的有效来源选择，最多覆盖3条来源、4项记忆及4000字符；整体记忆预算24000字符。这些是当前输入预算上限，不是遗忘配额。被隐藏、删除、其他分支或其他角色的内容不会因“近期”重新进入；迁入参考资料不当作近期共同经历。

阶段候选可在正常进程重启后继续使用，依赖、角色配置或模型配置变化时失效；迟到结果不能重建已失效记录。备份只保留权威状态，不复制未提交阶段候选；恢复后必要阶段重新处理。恢复旧备份仍合并目标数据库的参考删除边界并脱敏保存点中的旧内容。恢复到没有目标数据库的新路径无法获知备份之后发生的删除，仍遵循[恢复说明](RECOVERY.md)的 recovery 边界。

本批自动化证据包括真实 HTTP/SQLite + 模拟酒馆按钮操作、独立 CLI 进程与组件测试。它不代表当前运行中的酒馆已升级，也不代表真实模型连续性、首字延迟或长期体验通过。核心地址仍为桌面 localhost；手机远程连接未在本批提供。最新候选与验证范围见项目 `PROJECT_STATUS.md`。
